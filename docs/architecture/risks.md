# FULLA — Risk Register (MVP)

Scale for **P** (probability) and **I** (impact): low / med / high. "Lives in" = the component or ADR that owns the mitigation.
Deadline: 15 Dec 2026. Week 1 starts on 2 Nov 2026.
Risks marked **⚑ Accepted** are consciously not mitigated beyond what is written; they are listed again at the end.
Revision 28.10.2026: backend is Java/Spring Boot. Simplification 28.10.2026: in-memory sessions, hand-written API types from `docs/contracts/api.md`, local-only demo (Render + Neon optional), minimal CI. Risks about the optional deploy are kept but marked.

| R-T08 | Two backend devs create Flyway migrations with the same version number or conflicting schema changes. | med | low | Flyway fails at startup with "found more than one migration with version"; CI red after merging two PRs. | Timestamp versions (`V20261103_1200__…`); one open schema PR at a time; CI runs all migrations on a fresh embedded Postgres. | ADR-0004 |

| R-T10 | Brand-supplied content runs code for buyers: `javascript:` product URL, markup in names. | low | high | A card link with a non-http scheme in the DB; a test finds it. | `@HttpUrl` Bean Validation allows only `http`/`https` on the server; the same rule in the FE form; React escaping only, no `dangerouslySetInnerHTML`; links built by `withUtm()` with `rel="noopener noreferrer"`. | ADR-0009, ADR-0005 |
| R-T11 | Malicious or oversized upload: SVG with script, a renamed `.exe`, a 50 MB file. | low | high | Upload accepted with a wrong type; heap spike or `OutOfMemoryError`. | Magic-byte check for PNG/JPG/WEBP only (no SVG); `spring.servlet.multipart.max-file-size=5MB`; serve with stored `Content-Type` + `nosniff`. | ADR-0007, `ua.fulla.images` |

| R-T13 | Favourites merge goes wrong: likes lost on login, likes from another device overwritten, or a failed sync never retried. | med | high | After login the «Вподобане» counter drops; the same buyer sees different lists on two devices. | Union-only endpoint (`ON CONFLICT DO NOTHING`); the server response replaces local only after success; backend tests for merge with overlap, two devices, double like; FE test for failed request then retry. | ADR-0012, `features/favorites`, `ua.fulla.buyer` |
| R-T14 | Brand and buyer roles get mixed up in the single session: a buyer principal passes a brand check, or a login as one type silently keeps data of the other. | low | high | A buyer account opens `/brand/products`; a MockMvc test with a buyer session on `/api/brand/**` returns 200. | Authorities `ROLE_BRAND`/`ROLE_BUYER` from separate tables; login as the other type creates a new session (session fixation protection); one negative test per protected path group. | ADR-0006 |
| R-T15 | **Optional deploy only.** The Spring Boot JVM runs out of memory on Render's 512 MB free instance. | med | low | Render shows "out of memory" restarts. | `JAVA_TOOL_OPTIONS` (`MaxRAMPercentage=75`, `UseSerialGC`, small `Xss`); upload limit enforced. | ADR-0010 |
| R-T16 | Hand-written SQL and row mapping drift from the schema (renamed column, wrong type), found only at runtime. | med | med | `BadSqlGrammarException` or a null field in a response after a migration. | Repository tests per table on embedded Postgres in CI; SQL lives next to its repository class; migrations and repository changes in the same PR. | ADR-0004, ADR-0011 |
| R-T17 | Validation rules diverge between Bean Validation (backend) and the zod form schemas (frontend): the form accepts what the API rejects, or the reverse. | med | med | A user sees a generic error after submitting a form that looked valid; a test example passes on one side and fails on the other. | The backend is the authority and its error `fields` are shown on the form; one shared list of valid/invalid examples per rule (email, URL, price, name lengths) used by both JUnit and Vitest tests. | ADR-0005, ADR-0008, ADR-0011 |

## 2. Product (requirements and user behaviour)

| ID | Risk | P | I | Trigger | Mitigation | Lives in |
|---|---|---|---|---|---|---|
| R-P01 | The stories added on 28.10.2026 (US-21.1, US-02, US-03) are not planned or estimated, so they slip or are questioned at review. | med | high | Sprint board has no tasks for them by week 2. | Stories now exist with acceptance criteria and are In Scope in `requirements.md`; the lead plans them explicitly (see R-M01 order). | ADR-0006, ADR-0012, `docs/requirements.md` |
| R-P02 | **⚑ Accepted.** A brand or buyer forgets the password; there is no reset (A-01). | med | low | A user writes to the team. | Operator command `reset-password` (Spring `ops` profile). | ADR-0006 |
| R-P03 | **⚑ Accepted.** Anyone can register and publish inappropriate or fake-brand content to the anonymous public feed; no moderation (A-04). | low | high | A strange card appears in the feed during testing or demo. | Public URL shared only with reviewers; operator can unpublish via DB; consent text recorded (A-17). | — (no component; A-04) |
| R-P04 | The feed is empty or ends in seconds at the demo, so the swipe journey can't be shown. | med | high | Fewer than ~20 published cards in the demo DB; «Ви переглянули всі доступні речі» appears in the first minute. | `dev` seeder with ≥ 4 brands and ~30 cards; empty catalog reuses the "all viewed" state (US-08.1); a "reset my session" hint for demos (clear localStorage). | ADR-0004 (seed), `features/feed` |

| R-P06 | **⚑ Accepted.** A brand's product page goes 404 or the site is down after publishing; FULLA cannot detect it (no server fetch, A-15). | med | med | A buyer lands on a 404 in the new tab; the brand notices missing traffic in its own analytics. | «Перевірити посилання» before publishing (US-26); brand unpublishes/edits (US-31); see `integrations.md`. | ADR-0009, integrations.md |
| R-P07 | One brand with many cards dominates the feed (order by publish time, A-10), undermining "discover new brands" (journey step 3). | med | low | In the seeded demo, the first 10 cards are from one brand. | Seed interleaves brands by publish time; real interleaving is Post-MVP (US-11). | ADR-0009, seed |
| R-P08 | FE and BE implement different gates: draft completeness and "active profile" (G-02, G-05). | low | med | The cabinet allows an action the API rejects, or the reverse. | Rules fixed in the stories (US-25.1, US-22.1, US-31 S2); the API is the authority; same test examples on both sides (R-T17). | ADR-0005, ADR-0009 |
| R-P09 | **⚑ Accepted.** Prices and availability on FULLA go stale because brands update them by hand (sync is Post-MVP). | high | low | A buyer sees a different price on the brand site. | Brand unpublishes sold-out items (US-31); unpublish → edit → republish for price (A-06). | ADR-0009 |

| R-P12 | Buyer personal data (email + liked products) is stored without telling the buyer what is stored. | low | med | The registration form has no data note; a reviewer asks about personal data. | Note on the form (US-02 CL); no other buyer data collected (NFR-19); logout clears the device copy. | ADR-0012 |

## 4. Consciously accepted for the MVP

| ID | Accepted risk | Why acceptable now | Revisit when |
|---|---|---|---|
| R-P02 | No password reset | Demo-scale, operator command exists | Real users onboard |
| R-P03 | No moderation of the public feed | Feed shared only with reviewers | Public launch |
| R-P05 | Anonymous buyers can lose favourites (storage cleared, other device) | Registration is the fix and is offered (ADR-0012) | — |
| — | Viewed progress is per device, even for registered buyers (ADR-0012) | Liked cards are still hidden; only skipped cards can reappear | Cross-device progress is requested |
| — | One login per browser: brand and buyer can't be logged in at the same time (ADR-0006) | Demo uses different browsers; real users are rarely both | A person needs both roles daily |
| R-P06 | Broken brand links not detected | No server-side fetching (A-15, SSRF) | Post-MVP link checker / import (integrations.md) |
| R-P09 | Stale prices and availability | Sync is Post-MVP (US-27–US-30) | Import is built |
| — | Last write wins on concurrent draft edits (ADR-0009) | One person per brand (A-03), published cards read-only | Team accounts per brand |
| — | No click tracking; attribution only via `utm_source=fulla` (A-19) | Not required by US-32 | Traction must be shown to brands |
| — | Re-login after every server restart (in-memory sessions, ADR-0006) | Local demo; restarts are rare; anonymous favourites stay in the browser | The app is deployed to a host that sleeps (then Spring Session JDBC) |
| — | No public URL for reviewers (ADR-0010) | No story needs one; local demo + optional tunnel | Reviewers must test on their own devices |

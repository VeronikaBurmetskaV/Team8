4 · State machines

domain-model.md §4 · conditions in [brackets] · error codes from api.md §3.2

Brand Profile

domain-model.md §4.1 · the state is derived from name and consent_given_at (data-model.md §2.2)

  • Self-transitions: edit name/logo in Active or Consented (US-22.1). A rejected save keeps the state: PROFILE_INVALID (US-22.1 S2).
  • The consent checkbox is locked once saved; consentGiven:false → CONSENT_LOCKED (A-08).
  • After login: Incomplete → /brand/profile, otherwise /brand/products (US-21.1 CL).

Product Card

domain-model.md §4.2 · publish = one conditional UPDATE (data-model.md §4, T-1)

  • No final state: cards are never deleted (US-31 CL).
  • PUT on a Published card → CARD_NOT_EDITABLE. Publishing again sets a new publishedAt, so the card moves to the end of the feed (ADR-0009).
  • PUBLISH_FIELDS_MISSING is a defensive check and does not fire in the normal flow (US-31 note, G-02).

Card Impression (one card × one browser)

domain-model.md §4.3 · lives only in localStorage (viewedIds, favoriteIds)

  • A second press on the same card ID is ignored, because the guard is by ID and not by timer: the double «Пропустити» skips #5 and shows #6 (US-10 S2, ADR-0009).
  • No "back" (US-12) and no "remove from favourites" (US-17) in the MVP, so Liked and Skipped have no other exits.

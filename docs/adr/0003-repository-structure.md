# ADR-0003: Repository structure — one repo with `backend/`, `frontend/` and a committed OpenAPI contract

## Status
Proposed — 2026-10-28 (revised the same day: backend language changed to Java)

## Context
ADR-0001 gives a Spring Boot backend and a React frontend that share one contract: endpoints, request/response shapes and error codes. Local start must be as simple as possible after `git clone`, without Docker. Claude Code should see the whole system in one checkout.

## Options
1. **One repo: `backend/` (Maven Wrapper), `frontend/` (Vite), `contract/openapi.json`, root `package.json` with scripts only.**
   + Each pair uses its native tool day to day; one clone; root `npm run dev` starts both.
   − Two build tools in one repo; every laptop needs JDK 21 and Node.
2. **Maven multi-module; `frontend-maven-plugin` builds React.**
   + A single `./mvnw` drives everything.
   − FE devs run Maven for every change; Maven downloads its own Node; slower FE loop.
3. **Two repositories.**
   + Hard ownership boundaries.
   − The contract is copied between repos; two clones; Claude Code sees half the system.

## Decision
Option 1.

```
backend/           Spring Boot app (Maven Wrapper: mvnw, mvnw.cmd)
  src/main/java/ua/fulla/<feature>/
  src/main/resources/db/migration/   Flyway SQL
frontend/          React + Vite + TypeScript (ADR-0013)
  src/api/schema.d.ts                generated from contract/openapi.json
contract/
  openapi.json     generated by a backend test from springdoc, committed
scripts/           cross-platform Node scripts (dev start, API type generation)
docs/
package.json       root: scripts only; `workspaces: ["frontend"]` so one `npm install` installs the frontend
```
The contract flows one way: backend code → `contract/openapi.json` → `frontend/src/api/schema.d.ts`. Both generated files are committed, so FE devs don't need the backend running to get types.

## Consequences
- **Simpler:** one PR can change API + contract + UI together; FE devs never open Maven, BE devs rarely touch npm.
- **Harder:** generated files must be regenerated on every API change; CI fails if they are stale (ADR-0011).
- **Postponed:** build caching; publishing the contract as a package.

## Related stories
Cross-cutting; most visible for US-21, US-21.1, US-02, US-22.1, US-25.1, US-26 (forms whose rules and error codes cross the contract).

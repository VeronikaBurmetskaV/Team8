# Поле імені на формі входу (/login) — різне для покупця і бренду

Додати поле імені на форму входу (/login) — різне для покупця і бренду. Код: frontend/src/features/buyer-auth (LoginPage, форма входу покупця, useBuyerLogin), frontend/src/features/cabinet-auth (BrandLoginForm, api.ts), shared/messages.uk.ts; бекенд — POST /api/brand/login (і POST /api/buyer/login, якщо вже реалізований). Контекст: CLAUDE.md, docs/architecture/api.md (login, таблиця помилок), ADR-0006/ADR-0012, react-hook-form + zod, CSS Modules.

1. Форма входу:
   - таб «Вхід» (покупець): нове поле «Ваше імʼя» — першим, над «Email»; autocomplete="given-name";
   - таб «Вхід для бренду»: нове поле «Назва бренду» — першим, над «Email»; autocomplete="organization";
   - обидва обов'язкові: 1–50 символів після trim, не лише пробіли; помилки «Введіть імʼя» / «Введіть назву бренду»;
   - стиль, відступи й розмір — як в інших полях; «Забули пароль?» і решта без змін.

2. Перевірка на сервері:
   - POST /api/brand/login приймає { brandName, email, password }; вхід успішний лише якщо email+пароль правильні І brandName збігається з назвою бренду в профілі (порівняння: trim, нормалізація Unicode NFKC, без урахування регістру, кілька пробілів = один);
   - будь-яка невідповідність (email, пароль або назва) → та сама відповідь, що й зараз для неправильних даних (наприклад 401 INVALID_CREDENTIALS), однаковий час відповіді — не розкривати, яке поле неправильне; ліміт спроб — як зараз;
   - якщо в профілі бренду назви ще немає (старі акаунти) — поле назви не перевіряється (вхід за email+паролем), але й не зберігається; додай TODO;
   - покупець: якщо POST /api/buyer/login уже реалізований — так само з полем name і display_name з акаунта; якщо ні (заглушка «Вхід для покупців скоро запрацює») — поле лише валідується на фронтенді, а в useBuyerLogin додай name до тіла майбутнього запиту з TODO.
   - онови api.md (тіло login, примітка про порівняння назви/імені).

3. Тексти помилки входу на фронтенді: «Неправильні дані для входу. Перевірте імʼя, пошту й пароль» (для бренду — «назву бренду, пошту й пароль»).

4. Тести: поля є в обох табах з правильними підписами; порожнє поле — помилка, запит не відправляється; бекенд — правильна назва в іншому регістрі/з пробілами пускає; неправильна назва → 401 з тим самим кодом, що й неправильний пароль; старий акаунт без назви входить за email+паролем.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

# Кабінет бренду: квадратна картка профілю, одностороння згода, діалоги підтвердження

Правки кабінету бренду. Контекст: CLAUDE.md, ADR-0002 (кабінет desktop-first), shared/tokens.css, тексти українською через messages.uk.ts. Без JPA.

1. Прибери пункт «Додати товар» з верхньої навігації кабінету (панель угорі справа, Layout.tsx). У навігації лишаються лише: «Головна», «Профіль», «Товари», «Вийти». Кнопка «Додати товар» лишається тільки на головній /brand (велика, по центру) і на /brand/products.

2. Картка профілю бренду (і на /brand/profile, і картка профілю на головній /brand) має бути квадратною: aspect-ratio: 1 / 1, вміст вирівняний по центру, розмір — помітно більший за форму входу (через окрему змінну в tokens.css, не чіпати --auth-card-max-width). Якщо вміст не влазить у квадрат — картка росте по висоті, але текст ніколи не обрізається. На вузьких екранах (менше --bp-tablet) — на всю ширину, без примусового квадрата.

3. Згоду бренду НЕ можна прибрати після того, як її дали. Зараз її можна зняти навіть після натискання — це баг.
   a) Спершу перевір бекенд: чи BrandProfileService/BrandProfileRepository реально зберігають consent_given_at і consent_text (у main там був коментар «The consent is not processed yet»). Якщо ні — зроби одностороннє збереження за US-22.2, api.md і INV-09: умовний UPDATE ... WHERE consent_given_at IS NULL, текст згоди — серверна константа; consentGiven=false після згоди ігнорується (або як каже api.md). Тести на бекенді.
   b) На фронтенді: коли бренд ставить галочку, показати модальне вікно підтвердження: «Після підтвердження згоду не можна буде відкликати самостійно. Підтвердити?» з кнопками «Підтвердити» і «Скасувати».
      - «Скасувати» — галочка лишається знятою.
      - «Підтвердити» — згода одразу зберігається на сервері (не чекаючи кнопки «Зберегти» форми); поки йде запит — індикатор і заблокована галочка; після успіху галочка поставлена й заблокована (disabled) назавжди, поруч текст «Згоду надано <дата>». При помилці — повідомлення, галочка знята.
      - Після перезавантаження сторінки галочка теж поставлена й заблокована (стан береться лише з відповіді сервера).
   c) Тести: не можна зняти галочку після згоди; «Скасувати» не зберігає; після перезавантаження (новий запит профілю) галочка заблокована.

4. Підтвердження виходу: при натисканні «Вийти» в кабінеті показати модальне вікно «Ви точно хочете вийти з профілю?» з кнопками «Вийти» і «Скасувати». Вихід (logout) виконується лише після «Вийти»; «Скасувати», Esc або клік поза вікном — закривають без виходу.

5. Модальне вікно зроби одним перевикористовуваним компонентом у shared/ (наприклад ConfirmDialog) і використай його в пунктах 3 і 4:
   - на основі нативного <dialog> (showModal), щоб працювали фокус і Esc;
   - role/aria-labelledby, фокус на кнопці «Скасувати» при відкритті, повернення фокусу на кнопку, що відкрила вікно;
   - затемнений фон, анімація появи через motion; кольори з tokens.css; на мобільному вікно не ширше екрана.
   - Тест компонента: відкривається, Esc закриває, «Підтвердити» викликає колбек.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: npm run lint, npm run typecheck, npm test, npm run build, cd backend && ./mvnw verify. Коротко опиши змінені файли.

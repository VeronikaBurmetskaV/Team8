# Шапка покупця: мерехтіння і цикл станів при прокрутці

Сайт мерехтить і гальмує при прокрутці, особливо вгору біля верху сторінки: липка шапка «застрягає» між станами (логотип уже маленький, як у смужці, а чорна область ще висотою повної шапки) і швидко перемикається туди-сюди. Код: frontend/src/shared/BuyerHeader.tsx, BuyerHeader.module.css, headerState.ts, Layout.tsx, index.css, а також features/catalog/HeroBanner.tsx і shared/reveal.ts (можливі важкі ефекти). Контекст: CLAUDE.md, ADR-0002, CSS Modules, motion.

1. Спершу знайди причину і напиши мені (коротко, з доказами):
   - чи є зворотний зв'язок: зміна висоти шапки → зсув контенту → маркер IntersectionObserver / scrollY перетинає поріг → шапка знову перемикається (цикл);
   - чи впливає «пружинний» overscroll (на Mac/iOS scrollY буває від'ємним або більшим за максимум) і нещодавні правки overscroll-behavior / фону html;
   - чи анімується height/padding/font-size (перерахунок layout на кожен кадр) замість transform/opacity;
   - скільки разів за прокрутку ре-рендериться BuyerHeader і сторінка (React Profiler / лічильник у dev), чи не оновлюється стан на кожен scroll-подію;
   - чи гальмують backdrop-filter / filter: blur у HeroBanner, reveal-анімації карток, тіні.

2. Виправ так, щоб шапка ніколи не могла зациклитися:
   - шапка position: fixed, top: 0; під нею — постійний spacer ФІКСОВАНОЇ висоти, що дорівнює висоті повної шапки (не змінюється між станами). Тоді зміна вигляду шапки не зсуває контент і не впливає на scrollY.
   - стан full/compact визначається тільки за window.scrollY з гістерезисом: compact, коли scrollY > висоти повної шапки + 16 px; знову full, лише коли scrollY < 8 px. Значення scrollY обмежуй до [0, max] (ігноруй від'ємні при overscroll). Читання — у requestAnimationFrame, не частіше одного разу за кадр; setState тільки коли стан реально змінився.
   - прибери IntersectionObserver-маркер, якщо він залежить від висоти шапки.
   - перехід full ↔ compact: анімуються лише transform (scale/translate логотипа і вмісту) та opacity; висота фону шапки — через transform: scaleY на окремому фоновому шарі або clip-path, а не height. Тривалість ~250 мс; нова зміна стану під час анімації не запускає «стрибок» назад.
   - compactExpanded (розгорнута по стрілці) — так само без зміни spacer.
   - will-change ставити лише на час анімації, не постійно.

3. Продуктивність:
   - HeroBanner: розмиття фону — заздалегідь розмитою картинкою (або одним шаром з filter, без backdrop-filter, що перераховується при прокрутці); не анімувати blur при прокрутці.
   - reveal-анімації: IntersectionObserver з unobserve після першої появи, анімувати лише opacity/transform; prefers-reduced-motion — вимкнено.
   - scroll-слухачі лише passive: true; жодних setState на кожен scroll-подію в інших компонентах (перевір CatalogPage, BrandTiles, FilterPanel).

4. Перевір вручну і опиши: Chrome і Safari на Mac (тачпад, швидка прокрутка вгору/вниз, відтягування за верх), DevTools → iPhone; у Performance-записі прокрутки немає довгих кадрів (> 16 мс) і повторюваних Layout від шапки; шапка не мерехтить біля верху сторінки.

5. Тести: headerState — гістерезис (коливання scrollY навколо порогу не перемикає стан), від'ємний scrollY = full; spacer має однакову висоту в усіх станах; наявні тести проходять.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши причину і змінені файли.

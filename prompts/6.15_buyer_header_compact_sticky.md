# Шапка покупця: липка, згортається в тонку смужку

Липка шапка покупця, що згортається в тонку смужку. Код: frontend/src/shared/BuyerHeader.tsx, BuyerHeader.module.css, Layout.tsx, тексти — messages.uk.ts. Лише сторінки покупця; шапку кабінету бренду не чіпати. Контекст: CLAUDE.md, ADR-0002 (покупець mobile-first), shared/tokens.css, CSS Modules, motion.

1. Поведінка:
   - Нагорі сторінки шапка повна, як зараз (FULLA / SWIPING, місто, мова, іконки).
   - Коли користувач прокрутив нижче висоти повної шапки — вона перетворюється на тонку смужку, закріплену вгорі екрана (position: sticky/fixed, top: 0), висотою ~48 px, той самий темний фон.
   - У смужці: маленький логотип FULLA (без SWIPING) по центру — клік веде на / і прокручує нагору; справа кнопка-стрілка «Розгорнути меню» (іконка шеврона вниз).
   - Клік по стрілці (або по самій смужці, крім логотипа) — розгортає повну шапку поверх контенту під смужкою (не зсуваючи сторінку), з плавною анімацією висоти через motion. Стрілка повертається вгору, підпис «Згорнути меню».
   - Розгорнута шапка згортається назад: повторний клік по стрілці, Esc, клік поза нею, перехід на іншу сторінку, або прокрутка сторінки далі вниз більш ніж на ~40 px.
   - Повернення нагору сторінки — знову звичайна повна шапка.
   - Між станами немає стрибка вмісту сторінки: під липкою шапкою зарезервоване місце (або шапка завжди fixed, а main має відступ), щоб при переході повна ↔ смужка товари не підскакували.

2. Технічно:
   - Стан «прокручено» визначай через IntersectionObserver на невидимому маркері під повною шапкою (не через scroll-listener на кожен піксель); якщо потрібен scroll для «згорнути при прокрутці вниз» — з requestAnimationFrame/throttle.
   - Логіку станів (full / compact / compactExpanded) винеси в чистий reducer у окремий файл (наприклад shared/headerState.ts) з тестами.
   - prefers-reduced-motion: без анімації, лише миттєва зміна.
   - z-index шапки — вище за контент і бейджі, але нижче за модальні вікна (повна картка товару, ConfirmDialog, шухляда фільтрів). Якщо в tokens.css немає шкали z-index — додай.
   - Панель фільтрів каталогу (її закріплений заголовок і висота «до висоти вікна мінус шапка») і модалки обраного мають враховувати висоту смужки — заведи CSS-змінну --header-compact-height і використай її там.
   - Бейджі нових товарів, випадні списки міста й мови працюють і в розгорнутій шапці; випадні списки не обрізаються.
   - iPhone: враховуй safe-area (env(safe-area-inset-top)).

3. Доступність: кнопка розгортання з aria-expanded, aria-controls і aria-label «Розгорнути меню» / «Згорнути меню»; після розгортання фокус переходить на першу іконку; Esc закриває і повертає фокус на стрілку; уся шапка — <header> з <nav>.

4. Перевір на ширинах 320, 375, 768, 1024, 1440 px на сторінках /, /feed, /favorites: смужка не перекриває контент, свайп-жести на /feed не ламаються, горизонтального скролу немає.

5. Тести: reducer станів; при прокрутці показується смужка; клік по стрілці розгортає/згортає; Esc і перехід на іншу сторінку згортають; логотип у смужці веде на /.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

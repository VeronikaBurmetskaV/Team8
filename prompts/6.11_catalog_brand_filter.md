# Каталог: фільтр за брендами разом із фільтром за ціною

Фільтр за брендами в каталозі на головній (/). Код: frontend/src/features/catalog (FilterPanel.tsx, catalog.ts, CatalogPage.tsx), тексти — shared/messages.uk.ts. Фільтр за ціною вже є (?minPrice/?maxPrice, група «Ціна» з «+/−») — бренди мають працювати разом із ним і виглядати так само. Контекст: CLAUDE.md, ADR-0002 (mobile-first), shared/tokens.css, CSS Modules, motion. Товари беремо з GET /api/feed (поле brandName у FeedCard); бекенд і api.md не змінюємо.

1. Група «Бренд» у панелі фільтрів:
   - замість заглушки «Скоро» — згорнута група з «+» справа, як «Ціна»; по кліку розгортається («−»).
   - якщо вибрано хоча б один бренд — група відкрита, а біля заголовка кількість вибраних («Бренд · 2»).

2. Список брендів:
   - збирається з товарів каталогу: унікальні brandName (порівняння без урахування регістру й зайвих пробілів, щоб «CHER'17» і «Cher'17» були одним брендом; показуємо найчастіший варіант написання), відсортовані за алфавітом (localeCompare з 'uk'), біля кожного — кількість товарів у дужках.
   - чиста функція в catalog.ts: brandOptions(items) → [{ key, label, count }]. key — нормалізована назва (lowercase, trim).
   - кожен бренд — чекбокс з назвою (label клікабельний цілком); вибрані позначені галочкою. Стилі чекбокса — під палітру tokens.css, зона натискання ≥ 44 px.
   - якщо брендів більше 8 — показувати перші 8 і кнопку «Показати всі (N)».
   - поки товари вантажаться — «Завантаження…»; якщо брендів немає — група не показується.

3. Вибір кількох брендів:
   - клік по бренду ОДРАЗУ застосовує фільтр: оновлює URL на / з параметрами ?brand=<key>&brand=<key2> (повторюваний параметр), каталог перемальовується, скрол на початок списку. Панель лишається відкритою, щоб можна було вибрати ще.
   - повторний клік знімає бренд.
   - логіка: бренди між собою — АБО; бренди і ціна — І (товар має бути одного з вибраних брендів І в діапазоні цін).
   - чиста функція filterCatalog(items, { minPrice, maxPrice, brands }) у catalog.ts, яка застосовує всі фільтри разом (заміни нею окремі виклики filterByPriceRange). Розбір URL — окрема чиста функція parseFilters(searchParams); невідомі бренди з URL ігноруються.
   - на мобільному (панель — шухляда) внизу панелі закріплена кнопка «Показати N товарів» (N — скільки зараз підходить), яка закриває панель.
   - «Показати ще» і лічильники працюють з відфільтрованим списком; при зміні фільтрів — знову перша сторінка.

4. Активні фільтри над сіткою:
   - по одному чіпу на кожен вибраний бренд («Barricade ✕») і чіп ціни, якщо вона задана; ✕ прибирає лише цей фільтр.
   - якщо активних фільтрів більше одного — кнопка «Скинути все».
   - позначка на кнопці «Фільтри» показує кількість активних фільтрів (кожен бренд + ціна як 1).
   - у панелі біля заголовка «Фільтри» — теж «Скинути все», якщо є що скидати.
   - порожній результат: «Немає одягу за цими фільтрами» + «Скинути все».

5. Доступність: група брендів — fieldset з legend «Бренд»; чекбокси нативні (<input type="checkbox">) або з правильними role/aria-checked; після зміни фільтра оголосити кількість знайдених товарів через aria-live="polite" («Знайдено 12 товарів»).

6. Тести:
   - brandOptions: унікальність без урахування регістру, сортування, підрахунок;
   - filterCatalog: один бренд, кілька брендів (АБО), бренд + ціна (І), без фільтрів;
   - parseFilters: кілька ?brand, невідомий бренд, некоректна ціна;
   - клік по бренду додає його в URL, повторний — прибирає; чіп ✕ прибирає лише свій бренд; «Скинути все» прибирає все;
   - група «Бренд» згорнута і відкривається по «+».

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

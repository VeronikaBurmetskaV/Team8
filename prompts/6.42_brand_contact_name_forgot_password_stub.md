# Імʼя при реєстрації бренду і заглушка «Забули пароль?»

Ім'я при реєстрації бренду і заглушка «Забули пароль?». Код: frontend/src/features/buyer-auth (LoginPage, BuyerRegisterPage, CSS Modules), frontend/src/features/cabinet-auth (BrandLoginForm, BrandRegisterPage, api.ts), App.tsx (маршрути), shared/messages.uk.ts; бекенд — реєстрація бренду (ua.fulla… brand register), Flyway-міграції. Контекст: CLAUDE.md, docs/architecture/api.md, data-model.md, ADR-0004 (JdbcClient), ADR-0002, shared/tokens.css, CSS Modules, react-hook-form + zod. Стиль нових сторінок — як у /login (та сама ширина картки, поля, зелені головні кнопки).

1. Реєстрація покупця (/register): перевір, що поле «Імʼя» вже обов'язкове (1–50 символів після trim) на фронтенді й бекенді; якщо ні — зроби обов'язковим. Нічого іншого не змінюй.

2. Реєстрація бренду (/brand/register): нове обов'язкове поле «Ваше імʼя» (контактна особа бренду), перше у формі, перед «Назва бренду»:
   - zod: 1–50 символів після trim, не лише пробіли; помилка «Введіть імʼя»; autocomplete="name";
   - бекенд: POST /api/brand/register приймає contactName (обов'язкове, ті ж правила; 400 VALIDATION_FAILED з fields.contactName); Flyway-міграція — колонка contact_name varchar(50) в акаунті або профілі бренду (обери за data-model.md і поясни); наявні акаунти не ламати (NULL для старих або значення за замовчуванням — поясни вибір);
   - GET/PUT /api/brand/profile повертає і дозволяє змінити contactName; на /brand/profile поле «Контактна особа»;
   - онови api.md і data-model.md.

3. «Забули пароль?» — лише заглушка, без бекенду:
   - на /login в обох табах («Вхід» і «Вхід для бренду») під полем пароля праворуч — посилання «Забули пароль?» (дрібний текст, наведення — зелений);
   - веде на /forgot-password?for=buyer або /forgot-password?for=brand;
   - сторінка /forgot-password: заголовок «Відновлення пароля», текст «Введіть пошту, яку ви вказували при реєстрації», поле «Email» (для покупця — «Email або номер телефону», використай parseLoginId, якщо він є), кнопка «Надіслати»;
   - після валідації і натискання «Надіслати» — БЕЗ запиту на сервер — картка змінюється на повідомлення: «Скоро тут можна буде отримати лист для відновлення пароля. Поки що зверніться до команди FULLA.» і кнопка «Повернутися до входу» (→ /login або /login?tab=brand за параметром for);
   - логіку відправки винеси у хук useRequestPasswordReset з TODO «підключити ендпоінт відновлення пароля» — щоб потім змінити лише його;
   - посилання «Повернутися до входу» є і до відправки.

4. Доступність: поля з <label>, помилки через aria-describedby/aria-invalid; повідомлення-заглушка — role="status"; посилання «Забули пароль?» доступне з клавіатури.

5. Тести: реєстрація бренду без імені — помилка і запит не відправляється; бекенд — 400 з fields.contactName, успішна реєстрація зберігає contactName, профіль його повертає; «Забули пароль?» є в обох табах і веде на правильну адресу; на /forgot-password після «Надіслати» показується заглушка і немає запиту до API; «Повернутися до входу» веде на правильний таб.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

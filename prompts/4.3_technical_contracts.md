# Prompt: Технічні контракти (дані та API-інтерфейси)

Read `docs/analysis/requirements-digest.md` and all `docs/adr/*.md`. Create a sketch of the DevMatch technical solution in `docs/architecture/` — four documents and one visual page, no application code:

## 1 `overview.md`

For a new team member who needs to understand the system in 10 minutes: C4 level 1 (system context) and level 2 (containers) in mermaid; the list of components of each container with a one-phrase responsibility; the list of frontend pages mapped to stories; which external systems are real integrations and which are just links.

## 2 `domain-model.md`

For everyone who writes code or tests: entities, attributes with constraints (lengths, formats — from the AC), invariants, and state machines for Project, Role, Application in a mermaid `stateDiagram` with transition conditions. Each rule — with a reference to US-xx.

## 3 `api.md`

For the frontend and backend developer as a contract: a table endpoint → story → who has access → response code; a single error format and a dictionary of error codes derived from the Gherkin scenarios (400/401/403/404/409). Example request/response bodies — only for 3–4 non-trivial endpoints.

## 4 `data-model.md`

For whoever writes the DB schema: tables, fields, types, unique constraints, indexes, and separately — which invariants cannot be expressed by the schema and must live in the transaction code.

## 5 `system.html`

For a team meeting or the course owner: one self-contained HTML file (no external dependencies, opens from the file system) that shows the same system visually — context, containers with the API layers, the end-to-end scenario step by step, the three state machines, pages → stories, the nine decisions. Dark and light theme. It is a picture of the markdown documents, not a second source of truth: every label on it must be traceable to one of them.

## 6 Gaps and contradictions

If during the design you see that a story is not covered or contradicts another — don't resolve it silently, put it in the "Open questions" section in `overview.md`.

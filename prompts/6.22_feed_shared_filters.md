# Фільтри у свайпах (/feed), спільні з каталогом

Фільтри у свайпах (/feed) — ті самі, що в каталозі, і спільні з ним. Код: frontend/src/features/feed (FeedPage.tsx, queue.ts, FeedPage.module.css), frontend/src/features/catalog (FilterPanel.tsx, catalog.ts — parseFilters, filterCatalog, brandOptions, brandKey; чіпи фільтрів), посилання на /feed у HeroBanner.tsx і shared/BuyerHeader.tsx. Тексти — shared/messages.uk.ts. Контекст: CLAUDE.md, ADR-0002 (покупець mobile-first), shared/tokens.css, CSS Modules, motion. Бекенд і api.md не змінюємо. Обидві сторінки беруть товари з GET /api/feed, тож фільтрація на клієнті.

1. Спільний стан фільтрів:
   - джерело правди — параметри URL (?minPrice, ?maxPrice, ?brand=…), як у каталозі; для обох сторінок один хук, наприклад useCatalogFilters() (читання через parseFilters, запис через URLSearchParams), винеси його в shared або catalog і використай на / і на /feed.
   - при переході між / і /feed фільтри зберігаються: посилання на /feed (банер HeroBanner, іконка свайпу в шапці, будь-які інші) і назад на / додають поточні параметри фільтрів; зроби хелпер withFilters(path, filters).
   - додатково запам'ятовуй останні застосовані фільтри через shared/storage.ts: якщо користувач відкрив /feed або / без параметрів (наприклад з обраного чи за прямою адресою) — НЕ підставляй їх автоматично, але покажи над карткою/сіткою ненав'язливу кнопку «Повернути фільтри: …» (один клік застосовує). Скидання фільтрів очищує й збережене.

2. Фільтри на /feed:
   - кнопка «Фільтри» (як у каталозі, з позначкою кількості активних) над карткою, не перекриває картку і не заважає свайпу;
   - відкриває ТОЙ САМИЙ компонент FilterPanel, що й у каталозі, у вигляді шухляди на всіх розмірах екрана (на /feed немає бічної колонки); групи і поведінка ті самі: «Ціна» від–до з повзунком і кнопкою «Показати…», «Бренд» з кількома виборами, «Категорія одягу» і «Розмір» — як зараз («Скоро»);
   - кількість у кнопці «Показати N товарів» і кількість у брендах рахуються для свайпів по картках, які ще не переглянуті (pendingCards), а не по всіх.
   - під кнопкою «Фільтри» — чіпи активних фільтрів з ✕ і «Скинути все», як у каталозі.

3. Черга свайпів з фільтрами (queue.ts, FeedPage.tsx):
   - поточна картка і черга = pendingCards(filterCatalog(items, filters), progress); прогрес переглянутих (viewedIds/favoriteIds) НЕ скидається при зміні фільтрів — уже переглянуті картки не повертаються;
   - зміна фільтрів не повинна ламати анімацію картки, що відлітає (flying): нова черга застосовується після завершення анімації;
   - якщо під фільтри карток не лишилось — окремий порожній стан: «За цими фільтрами нових карток немає» і кнопки «Скинути фільтри» та «Дивитися каталог» (з тими ж фільтрами); відрізняй від стану «усе переглянуто» без фільтрів;
   - лайк/скіп, клавіатура, підказка «?» працюють як раніше.

4. Доступність: кнопка «Фільтри» з aria-expanded; після зміни фільтрів оголосити через aria-live «Залишилось N карток»; фокус після закриття шухляди повертається на кнопку «Фільтри».

5. Тести:
   - перехід / → /feed і назад зберігає параметри фільтрів;
   - на /feed показуються лише картки, що відповідають фільтрам; уже переглянуті не повертаються після зміни фільтрів;
   - порожній стан з фільтрами і кнопка «Скинути фільтри»;
   - «Повернути фільтри» з storage застосовує збережені фільтри, «Скинути все» очищує storage;
   - наявні тести queue і feed проходять.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

# Редизайн входу і реєстрації + назва й сайт у реєстрації бренду

Редизайн сторінок входу і реєстрації + нові поля реєстрації бренду. Код: frontend/src/features/buyer-auth (LoginPage, BuyerRegisterPage, CSS Modules), frontend/src/features/cabinet-auth (BrandLoginForm, BrandRegisterPage, api.ts, CSS Modules), frontend/src/features/cabinet-profile (BrandProfilePage, profileForm.ts), shared/tokens.css, shared/messages.uk.ts; бекенд — пакети реєстрації і профілю бренду, Flyway-міграції. Контекст: CLAUDE.md, docs/architecture/api.md (§ brand register / profile, таблиця помилок), data-model.md, integrations.md (правило A-15: сервер НЕ робить запитів на сайти брендів), ADR-0004 (JdbcClient, без JPA), ADR-0002, CSS Modules, react-hook-form + zod.

Частина 1 — візуал (сторінки /login з табами, /register, /brand/register):
1. Картка форми значно більша — приблизно вдвічі ширша, ніж зараз, і залежить від екрана, а не фіксована:
   - ширина: clamp(320px, 50vw, 880px) на десктопі, на планшеті ~80vw, на телефоні — на всю ширину мінус бічні відступи;
   - більші внутрішні відступи (через clamp з vw), більші поля (висота ≥ 52 px, шрифт на крок більший), більша кнопка;
   - картка по центру сторінки (по горизонталі; по вертикалі — з комфортним відступом від шапки, без порожнечі знизу на високих екранах);
   - винеси розміри в токени tokens.css (--auth-card-width тощо) і використай ОДНАКОВО на всіх трьох сторінках; таби на /login — тієї ж ширини, що й картка.
2. Таби «Вхід» / «Вхід для бренду» — зелені: колір із зеленого токена tokens.css (той, що в повзунку ціни; якщо його ще немає — додай --color-green). Активний таб: зелений фон і світлий текст; неактивний: зелений текст і зелена лінія знизу; hover/focus-visible — помітні. Контраст тексту ≥ 4.5:1 (якщо не проходить — затемни зелений і скажи, який вийшов). Головні кнопки форм («Увійти», «Створити акаунт», «Зареєструвати бренд») — теж зелені з тим самим контрастом.
3. Сторінка /brand/register вирівняна по центру так само, як /login (зараз вона притиснута вліво); заголовок «Реєстрація бренду» над карткою по центру; «Вже маєте кабінет? Увійти» — всередині картки внизу, як на /login.
4. Перевір на 320, 375, 768, 1024, 1440, 1920 px: нічого не вилазить, картка пропорційна екрану.

Частина 2 — нові поля реєстрації бренду:
5. Форма /brand/register: «Назва бренду» (обов'язкове), «Сайт бренду» (обов'язкове, placeholder «https://brand.com.ua»), «Email», «Пароль» (з оком). Валідація zod:
   - назва — ті самі правила, що в профілі (2–50 символів, як PROFILE_INVALID у api.md);
   - сайт — лише https://, валідний URL, довжина ≤ 2048; якщо користувач ввів без схеми (brand.com.ua) — автоматично додати https:// при втраті фокусу;
   - email і пароль — як зараз.
6. Бекенд:
   - Flyway-міграція: колонка website_url (varchar(2048), CHECK на https://) у таблиці профілю бренду (подивись data-model.md, де зберігається назва бренду);
   - POST /api/brand/register приймає { email, password, name, websiteUrl }; name і websiteUrl валідуються на сервері тими ж правилами; при успіху назва і сайт одразу записуються в профіль (у тій самій транзакції, що й створення акаунта). Стан профілю після реєстрації — за правилами domain-model.md (якщо назва заповнена, профіль більше не INCOMPLETE — перевір і зроби за моделлю);
   - нові коди помилок (наприклад BRAND_NAME_INVALID, WEBSITE_URL_INVALID) або повторне використання PROFILE_INVALID з fields.* — обери за стилем api.md і задокументуй;
   - сервер НЕ звертається за цим URL (A-15): жодної перевірки доступності сайту.
   - GET/PUT /api/brand/profile повертають і приймають websiteUrl; на /brand/profile — поле «Сайт бренду» для редагування.
7. Онови документацію: api.md (тіло запиту register, профіль, помилки), data-model.md (нова колонка), за потреби user story US-21 / US-22.1 (коротка примітка).
8. Тести: бекенд — реєстрація з назвою й сайтом, неправильний URL (http://, без домену), назва поза межами, профіль повертає websiteUrl; фронтенд — валідація нових полів, автододавання https://, помилки сервера під потрібними полями; таби зелені й активний таб позначено aria-selected.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

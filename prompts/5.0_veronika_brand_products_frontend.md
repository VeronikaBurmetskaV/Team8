# Промпт: Сторінки товарів бренду — список /brand/products і форма створення /brand/products/new

Implement two brand-cabinet pages in the frontend: the product list (`/brand/products`)
and the create-card form (`/brand/products/new`). Stories: US-25.1, US-26
(plus the list part of US-21.1 S1). Follow CLAUDE.md strictly. Frontend only, no CSS.

## 1 Scope

In: /brand/products (list of the brand's own cards) and /brand/products/new (form that creates a draft).

Out — do not build, leave no half-made UI: editing a card (`/brand/products/:id` stays
the current stub), preview (US-25.2), publish/unpublish buttons (US-31), profile and login
pages, card deletion, anything Out of Scope in CLAUDE.md §1.2, any CSS or visual design (§5).

## 2 Foundation (only what these two pages need)

1. Dependencies (CLAUDE.md §2.3 allow-list only): @tanstack/react-query,
   react-hook-form, zod, @hookform/resolvers. Add QueryClientProvider in main.tsx.
2. `src/api/types.ts` — add by hand from api.md:
   - PublicCard = { id, name, brandName, priceUah, photoUrl, productUrl }
   - BrandCard = PublicCard & { photoImageId: string | null; status: "DRAFT" | "PUBLISHED"; publishedAt: string | null; createdAt: string }
   - CreateProductRequest = { name; priceUah; photoImageId: string | null; photoUrl: string | null; productUrl }
   - ImageUploadResponse = { id; url }
3. `src/api/client.ts` — extend the existing wrapper (small, no `any`):
   - apiPost (JSON) and a multipart upload helper; both send X-XSRF-TOKEN with the
     value of the XSRF-TOKEN cookie and use credentials: "same-origin";
   - errors still become ApiError { status, code, fields }; 401 on /api/brand/** → redirect to /brand/login;
   - functions: getBrandProducts(), createBrandProduct(body), uploadImage(file);
   - POST /api/images is multipart (ADR-0007); the field name is not in the contract —
     use file and flag it in the report.
4. `src/shared/messages.uk.ts` — Record<ErrorCode, string>, texts verbatim from
   api.md §3.2. Codes with "—" (Q-08) get one neutral generic fallback; list them in the
   report. IMAGE_INVALID in the card form shows the US-25.1 S2 text.
5. `src/shared/validation.ts` — zod schema for the card form (rules in §4).

Feature components never call fetch directly.

## 3 Page /brand/products (list)

- GET /api/brand/products via TanStack Query; the server returns newest first — do not re-sort.
- Each row: photo thumbnail, name, price as 2400 грн (no thousands separator),
  status: DRAFT → «Чернетка», PUBLISHED → «Опубліковано».
- «Додати товар» link → /brand/products/new.
- States: loading, error with a retry button, empty list (short text + «Додати товар»).
- A broken thumbnail must not break the row (text placeholder / `alt`).
- A newly created card appears in the list (invalidate the query).

## 4 Page /brand/products/new (create form)

Reuse BrandProductPage (`id === "new"` branch). Fields in this order:
| Field (label) | Rule | Error code |
|---|---|---|
| «Назва товару» | trimmed, 1–100 chars | CARD_INVALID_NAME |
| «Ціна в грн» | integer, > 0, ≤ 1 000 000; -500, 0, text, decimals invalid | CARD_INVALID_PRICE_OR_PHOTO |
| «Фотографія товару» | exactly one of: file (PNG/JPG/WEBP, ≤ 5 242 880 bytes) or image URL starting with https:// | CARD_INVALID_PRICE_OR_PHOTO (server rejects file: `IMAGE_INVALID`) |
| «Посилання на товар на сайті бренду (URL)» | absolute URL, scheme http`/`https, non-empty host; «сукня», brand.ua/x invalid | CARD_INVALID_URL |

Exact texts:
- price/photo: «Вкажіть коректну ціну більше нуля та додайте фотографію товару»
- URL: «Введіть повне посилання на сторінку товару, що починається з https:// або http://»

Behaviour:
- The brand name is not a form field — the server takes it from the profile.
- «Перевірити посилання» next to the URL field opens the URL as entered in a new tab
  (`target="_blank" rel="noopener noreferrer"`); disabled while the URL is invalid (US-26 S2).
- «Зберегти чернетку»:
  1. validate with zod, show the message next to the wrong field;
  2. if a file was chosen: POST /api/images → take id;
  3. POST /api/brand/products with exactly one of photoImageId / photoUrl (the other null`), `priceUah as a number;
  4. on 201 → invalidate the list query, navigate to /brand/products.
- Server errors: map error.fields (`name`, priceUah, photoImageId`/`photoUrl,
  productUrl`) to the inputs via `messages.uk.ts; a code without fields is a form-level
  message. Keep all entered data on any 4xx.
- 409 PROFILE_INCOMPLETE → message with a link to /brand/profile.
- Disable submit while the request is running (UX only).
- No dangerouslySetInnerHTML; never put a javascript:`/`data: URL into href or src.

## 5 Styling — none

Do not write any CSS. Another person styles these pages later.

- No new .css / .module.css files, no changes to index.css, no inline style,
  no className for looks, no UI or CSS libraries.
- Plain semantic HTML only: <form>, <label> linked to its <input>, <button>,
  <ul>/<li> or <table>, <img alt>, <a>, headings; errors as plain text next to
  the field (e.g. `<p role="alert">`).
- Keep the markup clean so styles can be added later without touching component logic.

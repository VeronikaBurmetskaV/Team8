# Окремі повідомлення про помилки входу на /login

Окремі повідомлення про помилки входу (назва/імʼя, пошта, пароль) на /login. Код: frontend/src/features/cabinet-auth (BrandLoginForm, api.ts), frontend/src/features/buyer-auth (форма входу покупця, useBuyerLogin), shared/messages.uk.ts; бекенд — POST /api/brand/login (і POST /api/buyer/login, якщо реалізований), обробка помилок. Контекст: CLAUDE.md, docs/architecture/api.md (login, таблиця помилок), ADR-0006, ADR-0012, react-hook-form + zod.

Рішення: замість однієї загальної помилки входу показуємо, що саме не так. Задокументуй це в ADR (новий або доповнення до ADR-0006): свідомий компроміс — зручність проти можливості перевірити, чи зареєстрована пошта (account enumeration); захист — наявний ліміт спроб входу лишається і рахує всі невдалі спроби.

1. Перевірки на фронтенді (до відправки, як зараз, перевір що є):
   - порожнє поле — «Введіть назву бренду» / «Введіть імʼя», «Введіть email», «Введіть пароль»;
   - email у неправильному форматі — «Перевірте формат email».

2. Перевірки на сервері по черзі, перша невдала повертає свою помилку (400/401 з кодом і полем у fields):
   - пошта не знайдена → EMAIL_NOT_FOUND, fields.email: «Акаунт з такою поштою не знайдено» (+ на фронтенді посилання «Зареєструватися»);
   - пароль неправильний → WRONG_PASSWORD, fields.password: «Неправильний пароль» (+ посилання «Забули пароль?» поруч);
   - назва бренду не збігається (порівняння як зараз: trim, NFKC, без урахування регістру) → BRAND_NAME_MISMATCH, fields.brandName: «Назва бренду не збігається з вказаною при реєстрації»;
   - для покупця аналогічно NAME_MISMATCH, fields.name: «Імʼя не збігається з вказаним при реєстрації» (якщо вхід покупця ще заглушка — лише підготуй коди і тексти на фронтенді з TODO);
   - назва/імʼя перевіряються лише ПІСЛЯ правильних пошти й пароля (щоб не можна було дізнатися назву бренду без пароля);
   - ліміт спроб: усі ці невдачі рахуються; при перевищенні — наявна помилка 429 і текст «Забагато спроб. Спробуйте за кілька хвилин».

3. Фронтенд: кожна серверна помилка показується під своїм полем (червоним, aria-invalid, aria-describedby), фокус переходить на це поле; загальний текст «Неправильні дані для входу» прибрати (лишити лише для непередбачених помилок і 429).

4. Онови api.md: коди EMAIL_NOT_FOUND, WRONG_PASSWORD, BRAND_NAME_MISMATCH, NAME_MISMATCH у таблиці помилок і в описі login.

5. Тести: бекенд — кожен випадок повертає свій код і поле; назва не перевіряється при неправильному паролі (повертається WRONG_PASSWORD, не BRAND_NAME_MISMATCH); ліміт спроб рахує всі невдачі. Фронтенд — помилка під правильним полем для кожного коду, фокус на ньому, посилання «Зареєструватися» / «Забули пароль?» біля відповідних помилок.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

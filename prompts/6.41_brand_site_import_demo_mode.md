# Імпорт з сайту бренду в демо-режимі (без підтвердження власника)

Імпорт з сайту бренду в демо-режимі — без підтвердження власника, як демо-імпорт ADR-0014. Контекст: ADR-0014 (демо-імпорт лише в профілі dev, дані чужих сайтів ніколи не публікуються), новий ADR про імпорт з сайту бренду, integrations.md, api.md, CLAUDE.md. Код: бекенд — сервіс підтвердження сайту й імпорту (/api/brand/site/verify, /api/brand/import, /api/brand/import/status), конфігурація профілів (application-dev.yml тощо); фронтенд — features/cabinet-home (блок «Імпорт з сайту»), messages.uk.ts.

1. Поведінка за профілем (одне налаштування, наприклад fulla.brand-import.require-site-verification):
   - dev: false — підтвердження власника НЕ потрібне. Бренд вказує сайт у профілі → одразу доступна кнопка «Імпортувати товари з goldi.ua». Ніяких мета-тегів, файлів чи пошти, ніякої кнопки «Підтвердити для демо»;
   - prod/ops: true — як задумано в ADR (підтвердження обов'язкове). Значення за замовчуванням, якщо налаштування не задане, — true (безпечно).
   - перевірка робиться на бекенді: POST /api/brand/import у dev не вимагає site_verified_at; у prod без нього — 403 SITE_NOT_VERIFIED.

2. Статус для фронтенду: GET /api/brand/import/status повертає verificationRequired: boolean (і demoMode: boolean = !verificationRequired). Фронтенд вирішує, що показувати, лише з цих полів.

3. Фронтенд, блок «Імпорт з сайту»:
   - якщо verificationRequired = false: крок «Підтвердіть, що сайт ваш» НЕ показується взагалі; одразу поле «Посилання на товарний фід (необов'язково)» і кнопка «Імпортувати товари з <домен>»; над ними невелика сіра примітка «Демо-режим: товари імпортуються лише локально для розробки і не публікуються для покупців»;
   - якщо verificationRequired = true: як зараз (крок підтвердження).
   - якщо в профілі немає сайту — «Додайте сайт бренду в профілі» з посиланням на /brand/profile.

4. Публічність у демо-режимі: імпортовані товари поводяться так само, як товари демо-імпорту ADR-0014 — лише в локальній базі dev, не потрапляють у жодне публічне середовище (prod/ops). Перевір, що в prod/ops імпорт без підтвердження неможливий навіть прямим запитом до API.

5. Безпека запитів (захищений fetcher: лише https, заборона приватних адрес, robots.txt, паузи, ліміти) лишається і в dev — вимикається лише перевірка власника.

6. Документація: онови ADR про імпорт і ADR-0014 (коротко: у dev імпорт з сайту бренду працює без підтвердження, як демо-імпорт; у prod/ops підтвердження обов'язкове); api.md — поля verificationRequired/demoMode і поведінка 403.

7. Тести: dev — імпорт без підтвердження працює, блок підтвердження не рендериться, є примітка про демо-режим; prod — 403 SITE_NOT_VERIFIED без підтвердження; налаштування за замовчуванням = вимагати підтвердження.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

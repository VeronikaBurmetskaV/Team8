# Сторінка товарів бренду і синхронізація з сайтом бренду

Сторінка товарів бренду (/brand/products) і синхронізація з сайтом бренду. Код: frontend/src/features/cabinet-products (BrandProductsPage.tsx, CSS Module, queries.ts), features/cabinet-home (блок «Імпорт з сайту»), shared/messages.uk.ts, shared/tokens.css; бекенд — імпорт з сайту бренду (generic-імпортер, розклад автооновлення, збереження товарів, публікація). Контекст: CLAUDE.md, ADR про імпорт з сайту бренду, ADR-0014, ADR-0002 (кабінет desktop-first), api.md, domain-model.md, ADR-0004 (JdbcClient), CSS Modules.

1. Вигляд списку товарів:
   - прибери позначку «з сайту» біля назви (фільтр «Чернетки з сайту», якщо він є, лишається, але без бейджів у рядках);
   - рядки значно більші: фото ~120–160 px заввишки (пропорції одягу 3:4, object-fit: cover, заокруглені кути), назва більшим шрифтом, під нею ціна і статус («Чернетка» / «Опубліковано» / «Немає на сайті» — див. п. 3); відступи рядка більші; на вузьких екранах рядок стає карткою (фото зверху, текст під ним);
   - замість квадратних чекбоксів — круглі перемикачі вибору: коло ~24 px з рамкою ink; вибраний — зелене коло з білою галочкою; наведення — зелена рамка; focus-visible — обведення. Це має лишатися нативним <input type="checkbox"> (кастомний вигляд через CSS, appearance: none), щоб працювали клавіатура і скрінрідери; «вибрати всі» в заголовку — такий самий кружечок;
   - клік по всьому рядку (крім посилань і кнопок) перемикає вибір.

2. Синхронізація з сайтом бренду:
   - автоматичне оновлення для брендів з сайтом: інтервал — налаштування (наприклад fulla.brand-import.sync-interval), у dev — 1 година, у prod — 24 години; ліміт частоти і захищений fetcher лишаються;
   - кнопка «Оновити з сайту зараз» на /brand/products (і на головній кабінету) — запускає той самий імпорт з урахуванням обмеження частоти; поруч — «Оновлено: сьогодні о 14:32» і стан під час оновлення;
   - при кожній синхронізації:
     • нові товари з сайту → додаються як чернетки;
     • змінені (ціна, фото, розміри, наявність, опис) → оновлюються (крім полів, змінених брендом вручну — як було задумано);
     • товари, яких більше немає на сайті (лише після ПОВНОГО успішного прогону, як у CatalogSyncService) → отримують статус «Немає на сайті»: якщо були опубліковані — автоматично знімаються з публікації і зникають з каталогу й свайпів для покупців; опублікувати їх не можна (бекенд повертає 409 PRODUCT_NOT_ON_SITE; кнопка й кружечок вибору для них неактивні з підказкою «Цього товару більше немає на сайті бренду»);
     • якщо товар знову з'явився на сайті — статус повертається в «Чернетка» (не публікується автоматично);
   - товари «Немає на сайті» показуються внизу списку, приглушено, з кнопкою «Прибрати зі списку» (приховує їх із кабінету); через 30 днів — автоматично прибираються зі списку (дані не видаляються одразу — за domain-model.md);
   - вибраний товар у списку («Опублікувати вибрані») — якщо серед вибраних є «Немає на сайті», вони пропускаються з повідомленням «2 товари пропущено: їх немає на сайті».
   - Flyway: статус/позначка відсутності на сайті і час останньої синхронізації (якщо ще немає); онови api.md (статус товару, помилка PRODUCT_NOT_ON_SITE, поле lastSyncedAt) і ADR про імпорт (періодичність, поведінка при зникненні товару).

3. Тести: бекенд — новий товар з'являється чернеткою; зміна ціни оновлюється; зниклий товар отримує «Немає на сайті», знімається з публікації і не публікується (409); повернувся — знову чернетка; неповний прогін нічого не приховує; ручні зміни не перезаписуються. Фронтенд — немає бейджа «з сайту»; круглі перемикачі працюють з клавіатури; рядок «Немає на сайті» неактивний; «Опублікувати вибрані» пропускає такі товари з повідомленням; кнопка «Оновити з сайту зараз» і час оновлення.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

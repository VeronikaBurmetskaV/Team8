4.2 Package `ua.fulla.brandauth` (US-21, US-21.1)
- POST /api/brand/register → 201 { brandId, email, profileState: "INCOMPLETE" };
  inserts brand_accounts + an empty brand_profiles row in one transaction;
  the brand is logged in immediately.
- POST /api/brand/login → 200 { brandId, email, profileState }.
- POST /api/brand/logout → 204, session invalidated.
- Login is done manually (there is no `UserDetailsService`): verify the
  password with the encoder, build an authentication with ROLE_BRAND and a
  principal holding accountType and accountId, **save the
  SecurityContext to the HTTP session** (Spring Security 7 does not do it
  automatically for manual login) and change the session ID on login.
- Password: BCrypt, minimum 8 characters (`400 PASSWORD_TOO_SHORT`); never
  stored or logged in plain text.
- Email: normalized (`strip().toLowerCase(Locale.ROOT)`) before every insert
  and lookup; format name@domain.tld (`400 EMAIL_TAKEN_OR_INVALID`).
- Uniqueness only via the UNIQUE index: DuplicateKeyException →
  409 EMAIL_TAKEN_OR_INVALID. No check-then-insert.
- Unknown email or wrong password → the same 401 INVALID_CREDENTIALS.

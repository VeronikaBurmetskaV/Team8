# Промпт: Генерація User Stories

### 1️ Роль

Ти бізнес-аналітик, який спеціалізується на розробці вимог до вебпродуктів та **User Story Mapping**.

### 2️ Контекст

Ми розробляємо **FULLA** — вебплатформу-посередник між покупцями одягу та українськими брендами. Користувачі можуть переглядати товари різних брендів у форматі свайп-стрічки, зберігати вподобані речі, переглядати інформацію про них та переходити на сайт бренду для покупки.

> FULLA не здійснює оплату, оформлення замовлень і доставку. Каталог товарів розміщує та підтримує команда FULLA.

### 3️ Джерела

Використовуй результати попереднього аналізу цільової аудиторії та Value Proposition Canvas (Jobs, Pains, Gains) проєкту FULLA.

Враховуй основні потреби користувачів:
- швидкий пошук одягу;
- відкриття нових брендів;
- збереження вподобаних товарів;
- порівняння характеристик;
- зручний перехід до покупки на сайті бренду.

### 4️ Завдання

На основі готового User Journey з шести етапів згенеруй близько 20 користувацьких історій (User Stories) та структуруй їх у карту User Story Mapping.

#### Етапи User Journey

1. Знайомство та реєстрація.
2. Налаштування стрічки.
3. Перегляд товарів через свайп-стрічку.
4. Перевірка деталей товару.
5. Остаточний вибір у розділі «Вподобане».
6. Перехід на сайт бренду.

### 5️ Обмеження

- Формулюй кожну історію за шаблоном: **«Як [роль], я хочу [дія], щоб [цінність]»**.
- Враховуй основні й додаткові можливості платформи.
- Не додавай функцій оплати, доставки чи оформлення замовлень через FULLA.
- Не додавай функцій самостійного керування каталогом брендами.
- Не визначай, які історії належать до MVP або Post-MVP, оскільки це окреме завдання.
- Уникай дублювання історій і зайвих технічних деталей.

### 6️ Формат результату

Структурована карта User Story Mapping, у якій історії згруповані за шістьма етапами User Journey. Кожна історія повинна мати унікальний ідентифікатор: **US-01**, **US-02** тощо.

# Промпт: Публікація картки зі списку товарів бренду (US-31, US-22.2) — feature/publish-frontend

Реалізуй на фронтенді публікацію картки товару в стрічку зі сторінки `/brand/products`.
Сторії: US-31 (S1, S2, CL), US-22.2 (S2). Тільки `frontend/`, бекенд не чіпати.
Суворо дотримуйся CLAUDE.md (особливо §4.4, §5.2, §5.3, §6, §7).

## 1. Обсяг

**In:**

- кнопка «Опублікувати у стрічку» в рядку кожної картки зі статусом `DRAFT` у списку `/brand/products`;
- після успіху статус рядка — «Опубліковано»;
- якщо згоди немає — кнопка заблокована й показується підказка з посиланням на профіль.

**Out — не робити:** «Зняти з публікації» (окрема задача), редагування/прев'ю картки
(`/brand/products/:id`), видалення карток (його немає в MVP), зміни профілю чи чекбокса згоди,
будь-які Out-of-Scope сторії з CLAUDE.md §1.2, бекенд, нові залежності.

## 2. API-шар

1. `src/api/client.ts` — додай `publishBrandProduct(id: string): Promise<BrandCard>` →
   `` apiPost<BrandCard>(`/api/brand/products/${encodeURIComponent(id)}/publish`) `` без тіла.
   CSRF-заголовок і конверт помилки вже обробляє `request()` — не дублюй.
2. `src/api/types.ts` — нових типів не потрібно (`BrandCard`, `ProfileState` уже є). Не змінюй їх.
3. Фічі не викликають `fetch` напряму.

## 3. Логіка «чи можна публікувати» — чиста функція

Створи `src/features/cabinet-products/publishGate.ts` (без React):

```ts
type PublishGate =
  | { kind: "hidden" }          // картка вже PUBLISHED — кнопки немає
  | { kind: "loading" }         // профіль ще вантажиться — кнопка disabled, без підказки
  | { kind: "consentRequired" } // профіль не CONSENTED — кнопка disabled + підказка
  | { kind: "ready" };          // можна натиснути

export function publishGate(card: BrandCard, profileState: ProfileState | null): PublishGate
```

Правила:

- `card.status === "PUBLISHED"` → `hidden`;
- `profileState === null` (профіль ще не завантажено або помилка) → `loading`;
- `profileState !== "CONSENTED"` (`ACTIVE` або `INCOMPLETE`) → `consentRequired`;
- інакше → `ready`.

Стан згоди беремо тільки з `useBrandProfile()` (`profile.data.state`), не з localStorage
і не з власних прапорців. Перевірку заповненості полів у UI не роби: чернетка завжди повна (G-02),
сервер усе одно повертає `PUBLISH_FIELDS_MISSING`.

## 4. Хук мутації

У `src/features/cabinet-products/queries.ts` додай `usePublishBrandProduct()`:

- `mutationFn: (id) => publishBrandProduct(id)`;
- `onSuccess(card)`: заміни картку в кеші `brandProductsKey` через `setQueryData` (за `id`,
  порядок списку не змінювати), потім `invalidateQueries({ queryKey: brandProductsKey })` —
  лічильники «Опубліковано/Чернетки» на `/brand` теж оновляться;
- `onError`: для `INVALID_STATE` і `NOT_FOUND` — `invalidateQueries(brandProductsKey)` (список
  перечитується, api.md §3.2); для `CONSENT_REQUIRED` — ще й `invalidateQueries(brandProfileQueryKey)`.

Ніяких таймерів/debounce як гарантії — лише `disabled` під час запиту (UX, CLAUDE.md §6.10).

## 5. UI у `BrandProductsPage.tsx`

1. Додай у таблицю колонку дій (`<th scope="col">` з видимим або visually-hidden заголовком,
   наприклад «Дії»). Для кожного рядка — за `publishGate(card, profile.data?.state ?? null)`:
   - `ready` → `<button type="button">Опублікувати у стрічку</button>`; під час запиту саме цього
     рядка — `disabled` і `aria-busy`, інші рядки лишаються активними;
   - `loading` → та сама кнопка, `disabled`;
   - `consentRequired` → та сама кнопка, `disabled`, `aria-describedby` на підказку;
   - `hidden` → нічого (статус «Опубліковано» вже в колонці «Статус»).
2. Підказка про згоду — один раз над таблицею (не в кожному рядку), лише коли є хоча б одна
   чернетка і стан `consentRequired`:
   `<p id="publish-consent-hint">{messages.CONSENT_REQUIRED} <Link to="/brand/profile">…</Link></p>`.
   Текст — дослівно з `messages.CONSENT_REQUIRED` (US-31 S2 / US-22.2 S2), не переписувати.
   Текст посилання (історія його не дає) — додай у `cabinetHomeTexts` або новий об'єкт
   `publishTexts` у `messages.uk.ts`, позначивши `// PROVISIONAL`, напр. «Надати згоду в профілі».
3. Текст кнопки «Опублікувати у стрічку» — константа в `messages.uk.ts` (US-31 CL, дослівно).
4. Помилка публікації — `role="alert"` біля рядка (або над таблицею з назвою картки) через
   `errorMessage(error)` з `shared/errors.ts`. Для `UNAUTHENTICATED` нічого не показувати —
   клієнт уже перенаправляє на логін (як у `LoadError`).
5. Статуси «Чернетка» / «Опубліковано» — існуючий `statusText`, не змінювати.
6. Стилі: лише `BrandProductsPage.module.css` і токени з `shared/tokens.css`; без inline-style,
   без UI-бібліотек. Мобільний вигляд від 320 px без горизонтального скролу (рядки вже стають
   картками на телефоні — кнопка має вміщатися). Заблокована кнопка візуально відрізняється
   (`:disabled`), але текст читабельний.
7. Без `dangerouslySetInnerHTML`, без `any` (CLAUDE.md §6.9, §6.12).

## 6. Тести

Vitest, без нових бібліотек — як у `BrandHomePage.test.tsx`: `renderToString` +
`QueryClient` із заповненим кешем + `MemoryRouter`.

- `publishGate.test.ts`: `PUBLISHED` → `hidden`; `null` → `loading`; `INCOMPLETE` і `ACTIVE` →
  `consentRequired`; `CONSENTED` + `DRAFT` → `ready`.
- `BrandProductsPage.test.tsx`:
  - `CONSENTED` + чернетка → кнопка «Опублікувати у стрічку» без `disabled`, підказки немає;
  - `ACTIVE` + чернетка → кнопка `disabled`, є текст `CONSENT_REQUIRED` і посилання
    `href="/brand/profile"` (US-31 S2);
  - `PUBLISHED` картка → статус «Опубліковано», кнопки в рядку немає (US-31 S1);
  - без чернеток і без згоди → підказка не показується.
- `client.test.ts`: `publishBrandProduct` робить `POST /api/brand/products/{id}/publish` з
  `X-XSRF-TOKEN`; 409 `CONSENT_REQUIRED` → `ApiError` з цим кодом (mock fetch).
- Наявні тести не вимикати й не послаблювати.

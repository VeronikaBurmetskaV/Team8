# Падіння /brand через websiteUrl = undefined і сторінка помилки маршруту

Баг: після реєстрації бренду головна кабінету (/brand) падає з помилкою:
TypeError: Cannot read properties of undefined (reading 'trim')
  at withUtm (frontend/src/shared/links.ts:7)
  at websiteLink (frontend/src/features/cabinet-home/cabinetHome.ts:32)
  at ProfileHeader (frontend/src/features/cabinet-home/BrandHomePage.tsx:49)

1. З'ясуй, чому websiteUrl = undefined, і напиши мені причину:
   - чи POST /api/brand/register зберігає websiteUrl, чи GET /api/brand/profile повертає поле websiteUrl (перевір контролер, DTO, SQL-запит, Flyway-міграцію з колонкою website_url — чи вона є в цій гілці);
   - чи типи на фронтенді (api/types.ts, BrandProfile) збігаються з реальною відповіддю сервера (назва поля, null чи відсутній ключ);
   - чи профіль не береться з кешу react-query, створеного до реєстрації.
   Виправ причину (бекенд/типи/кеш), не лише симптом.

2. Зроби код стійким до відсутнього значення:
   - withUtm і websiteLink приймають string | null | undefined; порожнє, null, undefined або не-https значення → повертають null, без винятків;
   - ProfileHeader не показує посилання на сайт, якщо websiteLink повернув null;
   - у типі профілю websiteUrl — string | null (як у контракті api.md; онови api.md, якщо там інакше), і TypeScript strict не дає викликати .trim() без перевірки;
   - пошукай інші місця, де поля профілю бренду (name, websiteUrl, logo) використовуються без перевірки на null/undefined, і виправ їх так само.

3. Щоб одна помилка не валила весь сайт:
   - додай errorElement (або ErrorBoundary) для маршрутів у роутері: дружня сторінка «Щось пішло не так» українською, кнопки «Спробувати ще раз» (перезавантажити маршрут) і «На головну»; у dev-режимі під нею — текст помилки дрібно; у стилі сайту (tokens.css);
   - окремо для маршрутів кабінету (/brand/*) — та сама сторінка з кнопкою «До кабінету».

4. Тести: withUtm/websiteLink з undefined, null, "", "  ", http://, https:// (лише останнє дає посилання); BrandHomePage рендериться з профілем без websiteUrl; errorElement показується, коли компонент кидає помилку.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify (якщо змінював бекенд), npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши причину і змінені файли.

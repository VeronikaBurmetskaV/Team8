# Ліміт вподобаних товарів: гість 25, акаунт 100

Ліміт вподобаних товарів: гість — 25, з акаунтом — 100. Код: frontend/src/shared/productLists.ts (і все, що додає у вподобане: свайп вправо/«Сподобалось» у features/feed, сердечко в CatalogTile, модалка обраного), shared/messages.uk.ts; бекенд — POST /api/me/favorites (ua.fulla… favorites), api.md, ADR-0012. Контекст: CLAUDE.md, ADR-0002, CSS Modules, motion.

1. Константи в одному місці (frontend і backend): FAVORITES_LIMIT_GUEST = 25, FAVORITES_LIMIT_ACCOUNT = 100.
   - якщо зараз існує два окремі списки («вподобане» і «вподобане зі свайпів») — з'ясуй, і ліміт рахуй для того списку, який показується як «Вподобане»; якщо їх два — для їх об'єднання без дублів. Напиши мені, як зроблено.

2. Хто користувач: хук useFavoritesLimit() повертає ліміт за станом входу покупця. Вхід покупця ще не реалізований (US-03) — поки що завжди гість (25); залиш TODO з посиланням на US-03, щоб коли з'явиться сесія покупця, хук повертав 100.

3. Поведінка при досягненні ліміту:
   - додати товар, якщо він уже є у вподобаному, — як зараз (без змін і без попередження);
   - спроба додати новий товар понад ліміт (26-й для гостя / 101-й для акаунта) — товар НЕ додається, і показується вікно (shared ConfirmDialog або подібний компонент, не системний alert):
     • гість: заголовок «Вподобане заповнене (25 з 25)», текст «Щоб зберігати до 100 товарів, створіть акаунт. Або звільніть місце у вподобаному.», кнопки «Зареєструватися» (→ /register), «Перейти у вподобане» (→ /favorites), «Скасувати»;
     • акаунт: «Вподобане заповнене (100 з 100)», «Видаліть кілька товарів, щоб додати нові.», кнопки «Перейти у вподобане» і «Скасувати».
   - у свайпах: якщо ліміт досягнуто, свайп вправо / «Сподобалось» показує це вікно, а картка НЕ зникає й не позначається переглянутою (користувач може свайпнути вліво або звільнити місце); свайп вліво працює як завжди.
   - у каталозі: сердечко не заповнюється, показується те саме вікно.
   - на сторінці «Вподобане» біля заголовка — лічильник «18 з 25» (колір попередження, коли лишилось ≤ 3).

4. Бекенд (POST /api/me/favorites):
   - якщо після об'єднання кількість перевищила б 100 — додаються лише нові ID до досягнення 100 (у порядку з запиту), решта не зберігається; відповідь — повний список і поле skippedIds (ті, що не влізли); якщо додати нічого не вдалося — 409 FAVORITES_LIMIT_REACHED. Обмеження «> 500 IDs у запиті» лишається.
   - онови api.md (§ favorites, таблиця помилок) і ADR-0012 (ліміти 25/100 і що відбувається при злитті після входу: гостьові 25 + серверні не можуть разом перевищити 100, зайві не переносяться, і користувачу показується повідомлення).
   - тести бекенду: рівно 100; спроба 101-го — 409; злиття з частковим переносом і skippedIds.

5. Тести фронтенду: гість може додати 25, 26-й не додається і відкриває вікно; повторне додавання вже доданого товару не відкриває вікно; у свайпах картка лишається на місці при ліміті; лічильник «N з 25».

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.

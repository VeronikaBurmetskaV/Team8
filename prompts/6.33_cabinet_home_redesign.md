# Редизайн головної сторінки кабінету бренду (/brand)

Редизайн головної сторінки кабінету бренду (/brand). Код: frontend/src/features/cabinet-home (або де зараз сторінка /brand), cabinet-profile (useBrandProfile, BrandProfilePage), cabinet-products (useBrandProducts), shared/Layout.tsx (шапка кабінету), shared/messages.uk.ts, shared/tokens.css. Контекст: CLAUDE.md, ADR-0002 (кабінет desktop-first), docs/architecture/api.md (профіль бренду: name, consentGiven, consentGivenAt, websiteUrl, logo, profileState), domain-model.md (правила публікації і згоди), CSS Modules, motion. Бекенд змінюй лише якщо знайдеш баг з назвою (п. 1).

1. Назва бренду:
   - на головній кабінету має показуватись назва, введена при реєстрації. Зараз показано «Ще не вказана» — з'ясуй чому: чи POST /api/brand/register зберігає name у профіль, чи GET /api/brand/profile його повертає, чи фронтенд бере правильне поле, чи кеш react-query не застарів після реєстрації (інвалідуй профіль після реєстрації/входу). Виправ причину і напиши мені, що було.
   - якщо назви справді немає (старі акаунти) — замість неї «Назва не вказана» і кнопка «Додати назву» → /brand/profile.

2. Верхній блок — «шапка профілю» замість квадратної картки профілю (картку прибери):
   - на всю ширину контейнера, горизонтальний: зліва логотип бренду (кругле зображення ~88–120 px; якщо логотипа немає — кругла монограма з перших літер назви, у кольорах tokens.css), поруч назва бренду великим заголовком (шрифт заголовків), під нею посилання на сайт бренду (якщо є websiteUrl; відкривається в новій вкладці, rel="noopener noreferrer") і рядок статусу згоди («Згоду надано 24.11.2026» зеленою позначкою або «Згоду не надано» сірою);
   - справа кнопка «Редагувати профіль» (другорядна, з рамкою; наведення — зелена) → /brand/profile;
   - на вузьких екранах блоки стають один під одним, нічого не вилазить.

3. Повідомлення про згоду (лише коли згоди немає):
   - під шапкою профілю — помітна, але не тривожна плашка (світлий фон з tokens.css, зелена ліва смуга або іконка інформації);
   - текст: заголовок «Покупці поки не бачать ваших товарів», під ним «Щойно ви підтвердите згоду на показ матеріалів, опубліковані товари з'являться в стрічці FULLA.»; кнопка «Підтвердити згоду» → /brand/profile з прокруткою/фокусом на галочці згоди (наприклад /brand/profile#consent).
   - перевір у domain-model.md і бекенді, що саме блокує згода (публікацію чи показ покупцям), і підлаштуй текст під реальне правило, не змінюючи його суті; якщо правило інше — скажи мені.
   - коли згоду дано — плашки немає.
   - Повідомлення «Спочатку збережіть назву бренду в профілі» показуй лише якщо назви справді немає (окремою такою ж плашкою), а не завжди.

4. Блок «Товари» — великий і по центру:
   - картка по центру сторінки під плашками, ширина ~ clamp(320px, 60vw, 960px);
   - заголовок «Товари», три великі показники в ряд: «Усього», «Опубліковано», «Чернетки» (великі числа шрифтом заголовків, підписи дрібно; на телефоні — в стовпчик або 3 в ряд, якщо влазять);
   - головна велика кнопка «Додати товар» по центру картки (зелена, як інші головні кнопки) → /brand/products/new; якщо назви немає — кнопка неактивна з підказкою чому;
   - під нею посилання «Усі товари» → /brand/products;
   - якщо товарів немає — у картці текст «У вас поки немає товарів. Додайте перший — це займе кілька хвилин.» замість окремого сірого тексту під плашкою;
   - стани завантаження (скелетон) і помилки (LoadError, «Спробувати ще раз»).

5. Шапка кабінету (Layout, вгорі сторінки): зараз виглядає зламаною — білий фон, обрізаний логотип, порожня рамка і чорний прямокутник праворуч. Перевір і виправ, щоб вона була охайною (логотип FULLA видно повністю, навігація «Головна / Профіль / Товари / Вийти» вирівняна, без порожніх рамок; стан фокуса — лише з клавіатури). Шапку покупця не чіпай.

6. Доступність: шапка профілю — <section> з aria-labelledby на назву бренду; плашки — role="status"; кнопки з чіткими підписами; контраст ≥ 4.5:1.

7. Тести: назва з профілю показується; без згоди — плашка з кнопкою «Підтвердити згоду»; зі згодою — без плашки, видно дату; без назви — окрема плашка й неактивна «Додати товар»; лічильники товарів; монограма, коли немає логотипа.

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: npm run lint, npm run typecheck, npm test, npm run build (і cd backend && ./mvnw verify, якщо змінював бекенд). Коротко опиши причину проблеми з назвою і змінені файли.

### 4. Завдання

#### 4.1. Package ua.fulla.images — Photo upload & serving (ADR-0007)
Implement minimal, contract-compliant image storage so both https:// photo URLs and uploaded files (photoImageId) work end-to-end:
- Create the ImageStore interface (the single allowed abstraction per CLAUDE.md §2.1) and its PostgreSQL bytea implementation using JdbcClient.
- **POST /api/images** (ROLE_BRAND, brand ID from session principal):
- Accepts multipart/form-data with field file.
- Validates file size (<= 5 242 880 bytes) and detects MIME type strictly by magic bytes (PNG 89 50 4E 47, JPEG FF D8 FF, WEBP RIFF....WEBP — never by filename extension or client Content-Type; reject SVG and empty/corrupt files with 400 IMAGE_INVALID).
- Inserts into images and returns 201 Created with { "id": "<uuid>", "url": "/api/images/<uuid>" } (matching api.md).
- **GET /api/images/{id}** (public read so thumbnails render in browser):
- Returns 200 OK with raw bytes, stored Content-Type, X-Content-Type-Options: nosniff, and Cache-Control: public, max-age=31536000, immutable, or 404 NOT_FOUND if missing.

#### 4.2. Package ua.fulla.products — Create draft & list brand products (US-25.1, US-26)
Implement ProductController, ProductService, ProductRepository, and request/response Java records:
- **POST /api/brand/products** (ROLE_BRAND, brand ID taken ONLY from the authenticated session principal):
- Request body: { "name": "...", "priceUah": 2400, "photoImageId": "<uuid>|null", "photoUrl": "https://...|null", "productUrl": "https://..." }.
- Validation & Business Rules:
- name: trimmed, 1–100 characters (@NotBlank, length 1..100) → otherwise 400 CARD_INVALID_NAME with fields.name.
- priceUah: integer > 0 and <= 1 000 000 → otherwise 400 CARD_INVALID_PRICE_OR_PHOTO with fields.priceUah.
- Photo XOR rule: exactly one of photoImageId or photoUrl must be provided (the other null).
- If neither or both are provided → 400 CARD_INVALID_PRICE_OR_PHOTO.
- If photoUrl is provided → must be a valid URL starting strictly with https:// and non-empty host → otherwise 400 CARD_INVALID_PRICE_OR_PHOTO with fields.photoUrl.
- If photoImageId is provided → must exist in images AND belong to the current session's brand_id (T-8); if not found or belongs to another brand → 404 NOT_FOUND or 400 CARD_INVALID_PRICE_OR_PHOTO per api.md.
- productUrl: valid absolute URL (java.net.URI, scheme http or https, non-empty host) → otherwise 400 CARD_INVALID_URL with fields.productUrl. Store the URL as-is (never append utm_source on the backend).
- **Brand profile completeness gate (T-2, INV-11)**: A brand can create cards ONLY if its brand_profiles.name is already saved (name IS NOT NULL). Enforce this atomically in SQL/transaction; if name IS NULL, reject with 409 PROFILE_INCOMPLETE.
- Inserts into products with status = 'draft', published_at = null.
- Returns 201 Created with BrandCard JSON:
{ id, name, brandName, priceUah, photoImageId, photoUrl, productUrl, status: "DRAFT", publishedAt: null, createdAt }
(where photoUrl in response resolves to /api/images/{photoImageId} if uploaded, or the stored photo_url if external — verify exact contract in api.md, and brandName is joined from brand_profiles, never stored in products per INV-03).
- **GET /api/brand/products** (ROLE_BRAND, brand ID taken ONLY from the authenticated session principal):
- Queries ONLY products belonging to the session's brand_id (INV-07, T-7), joined with brand_profiles to get brandName.
- Ordered newest first (created_at DESC, id DESC).
- Returns 200 OK with the list of BrandCard items (or { "items": [...] } — strictly match api.md §2.1!).

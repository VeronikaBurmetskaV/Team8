# 500 при збереженні сайту бренду і очищення посилання

Баг: на /brand/profile після зміни поля «Сайт бренду» (наприклад https://goldi.ua/?srsltid=AYCX9vJHexSw4L6lxjK6NU…) і натискання «Зберегти профіль» показується «Сервіс тимчасово недоступний. Спробуйте пізніше» — тобто PUT /api/brand/profile повертає 5xx.

Помилка з логу бекенду:
<вставити помилку з терміналу>

Код: бекенд — пакет профілю бренду (контролер, сервіс, репозиторій, валідація websiteUrl), Flyway-міграція з колонкою website_url; фронтенд — features/cabinet-profile (BrandProfilePage, profileForm.ts, api), shared/links.ts. Контекст: CLAUDE.md, docs/architecture/api.md (профіль, таблиця помилок), integrations.md (A-15: сервер не звертається за URL), ADR-0004 (JdbcClient).

1. Відтвори і знайди причину (напиши мені):
   - чи є колонка website_url у базі цієї гілки (міграція застосована? flyway_schema_history), чи SQL у репозиторії оновлює її;
   - чи падає валідація/CHECK на URL з query-параметрами або довгими URL і чи виняток з бази (DataIntegrityViolation тощо) перетворюється на 500 замість 400;
   - чи збігаються назви полів у запиті фронтенду і DTO бекенду.
   Виправ причину.

2. Валідація посилання (однакова на фронтенді і бекенді, як у реєстрації бренду):
   - дозволено https:// з будь-яким шляхом і query-параметрами, довжина ≤ 2048;
   - перед збереженням нормалізувати: trim; прибрати трекінгові параметри (srsltid, utm_*, fbclid, gclid) — залишити лише origin + шлях + інші параметри; якщо після цього лишилось лише «?» — прибрати його;
   - нормалізацію винеси в чисту функцію на бекенді і таку ж на фронтенді (на фронтенді — при втраті фокусу поле показує вже очищене посилання).
   - некоректне значення → 400 з кодом із api.md (той самий, що при реєстрації, наприклад WEBSITE_URL_INVALID або PROFILE_INVALID з fields.websiteUrl), а НЕ 500; на фронтенді — помилка під полем «Сайт бренду».

3. Загальна обробка помилок бекенду: будь-яке порушення обмежень бази при збереженні профілю повертає 400 з відповідним полем, а не 500; несподівані винятки логуються з повним стектрейсом.

4. Тести: бекенд — збереження https://goldi.ua/?srsltid=… зберігає https://goldi.ua/ ; URL з корисними параметрами (?lang=uk) зберігається з ними; http:// і сміття → 400 з fields.websiteUrl; дуже довгий → 400; фронтенд — помилка під полем, а не загальне «Сервіс недоступний».

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: cd backend && ./mvnw verify, потім npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши причину і змінені файли.

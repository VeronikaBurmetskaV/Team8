# Фільтр «Розмір» і новий вигляд кнопки «Фільтри»

Фільтр «Розмір» і новий вигляд кнопки «Фільтри». Код: frontend/src/features/catalog (FilterPanel.tsx, catalog.ts — parseFilters, filterCatalog, brandOptions; CatalogPage.tsx, чіпи фільтрів, CSS Modules), спільний хук фільтрів (useCatalogFilters), якщо є — бо фільтри спільні для / і /feed; тексти — shared/messages.uk.ts. Контекст: CLAUDE.md, docs/architecture/api.md §2.2 (FeedCard.sizes: [{ label, available }], лише в імпортованих картках; у карток брендів поля немає), ADR-0002, shared/tokens.css, CSS Modules, motion. Бекенд не змінюємо.

1. Кнопка «Фільтри» (і на /, і на /feed):
   - за замовчуванням чорна (фон ink, світлий текст і іконка);
   - при наведенні мишкою і focus-visible — зелена (зелений токен з tokens.css), плавний перехід ~150 мс;
   - позначка кількості активних фільтрів лишається і читається на обох фонах.
   - заголовки груп у панелі («Категорія одягу», «Розмір», «Ціна», «Бренд») — чорні, при наведенні текст і «+/−» зелені.

2. Список розмірів:
   - збирається з карток каталогу (поле sizes), лише розміри з available: true;
   - нормалізація: trim, верхній регістр для літерних (m → M), уніфікація варіантів («one size», «onesize», «universal», «універсальний», «єдиний» → «One size»); складені на кшталт «XS/S» лишаються окремим розміром як є; винеси в чисту функцію sizeKey(label) у catalog.ts;
   - сортування: спершу літерні в порядку XXS, XS, S, M, L, XL, XXL, 3XL, 4XL (з варіантами 2XL = XXL), потім складені (XS/S, S/M …) за першою частиною, потім числові за зростанням (26, 28, 42, 44 …), «One size» — в кінці; чиста функція sizeOptions(items) → [{ key, label, count }], count — скільки товарів має цей розмір у наявності.

3. Група «Розмір» у панелі (замість заглушки «Скоро»):
   - згорнута з «+», як інші групи; відкрита, якщо вибрано хоча б один розмір; біля заголовка кількість вибраних («Розмір · 2»);
   - розміри — кружечки (круглі кнопки однакового розміру, ≥ 44 px), у рядок з переносом; текст розміру по центру, для довгих («One size», «XS/S») — кружечок розширюється в пігулку, не обрізаючи текст;
   - стан за замовчуванням: рамка і текст чорні, фон прозорий; наведення — рамка і текст зелені; вибраний — зелена заливка, світлий текст; focus-visible — помітне обведення; контраст ≥ 4.5:1;
   - кілька розмірів можна вибрати одночасно; клік одразу застосовує фільтр (як бренди): оновлює URL ?size=<key>&size=<key2>, каталог перемальовується, скрол на початок списку, панель лишається відкритою; повторний клік знімає розмір;
   - кнопки — <button aria-pressed>, група — fieldset з legend «Розмір».

4. Логіка фільтрації (filterCatalog / parseFilters):
   - розміри між собою — АБО (товар має хоча б один з вибраних розмірів у наявності); з брендами й ціною — І;
   - «точно є цей розмір»: показуються лише товари, де розмір є в sizes з available: true; товари без поля sizes (картки брендів) при активному фільтрі розміру НЕ показуються;
   - невідомі розміри з URL ігноруються;
   - працює і в каталозі, і у свайпах (/feed), бо фільтри спільні.

5. Активні фільтри: чіп на кожен розмір («Розмір M ✕»), враховується в «Скинути все» і в лічильнику на кнопці «Фільтри»; порожній результат — як для інших фільтрів.

6. Тести: sizeKey (регістр, пробіли, варіанти «One size»); sizeOptions (сортування літерні → складені → числові → One size; лише available); filterCatalog з розмірами (один, кілька — АБО, з брендом і ціною — І, картки без sizes виключаються, недоступний розмір не рахується); кружечок перемикає ?size у URL; чіп ✕ знімає розмір; кнопка «Фільтри» має окремий стан наведення (клас/стиль).

Збережи цей промпт у prompts/ з наступним номером.
Наприкінці: npm run lint, npm run typecheck, npm test, npm run build. Коротко опиши змінені файли.
